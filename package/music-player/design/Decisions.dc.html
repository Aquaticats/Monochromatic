MUSIC PLAYER · SLINT + JETPACK COMPOSE
Where the design stands
Everything settled so far, and every thread still open with my current thinking on it. Push on any numbered item.
Settled
Material 3
One identity on Mac, Linux, Windows, Android. Chosen because an unestablished system leaves every state undefined, your argument, and the decisive one.
True black, one theme
Surfaces #000 / #0A0A0D / #121216 / #1A1A1F. Outlines carry separation instead of lightness, because near-black tonal steps band on OLED.
48dp everywhere
One density scale. Desktop inherits the Android minimum rather than maintaining two spacing systems.
No library
The filesystem is the truth. One remembered path, restored on launch, session state, not a curated root.
Two-line track rows
Title above, duration · format · true peak below. No columns, no album art.
Folder picker
Wrapped plain-text targets in A to Z letter rows, a jump strip, and a drag bubble. Not chips, not one-per-row, ~1000 folders have to stay reachable.
Segmented buttons
One outer container, content-width segments, never stretched. Wraps to a grid with flush edges. Reads “Shuffle Camellia”, truncating.
True peak
Auto-applied. Full scan on first launch, on-demand under a second before playing an unscanned track. dB values visible in the list.
Scan progress
Bottom bar, only while running. It squeezes the list's scroll viewport, so nothing above it ever moves.
Nothing on the seam
Unfolded: halves with the gutter on the crease. Tabletop: the list flows continuously and steps around the crease with a gap.
Panes, not modals
Picker and Settings replace the track list. One pattern, no modal layer, survives every size and the fold.
Also settled
No queue, the folder is the play order. OS titlebar. Flat artist subdirectories. Volume is the only audio control. Resume exactly where you left off, paused.
Open: my current thinking, argue with it
O1
Open vs the picker
Because you restore into a folder, Open is navigation, not startup. My read: the picker switches folder within the current directory; Open moves to a different directory tree. Both permanent and visible, different jobs, neither redundant. Unresolved: whether Open replaces the remembered path or stacks a second one.
O2
The left half, unfolded
In fold-f the controls half has slack once the deck is laid out. Candidates: leave it quiet, put the folder list there permanently, or let the now-playing block grow into it. I lean toward the folder list, since it's the one thing you interact with most and the crease gives it a natural boundary.
O3
What Settings contains
You want it to exist for future expansion. Today the honest contents are: the filename-to-title rule, resume behaviour, and the scan's CPU policy. That's three rows, a near-empty pane designed to grow, not a settings screen pretending to be full.
O4
The first hour
A brutal full scan on first launch needs a one-time explanation, or it reads as a bug. My instinct: explain it in the empty state before anything is open, not as a dismissible banner over a working player.
O5
Subfolders inside a folder
Artist folders are flat today, but a filesystem doesn't promise that. If one contains an album subdirectory, the current design has nowhere to show it. Cheapest honest answer: show subfolders as rows above the tracks, and let one level of depth exist without inventing a breadcrumb.
O6
End of folder
“In order” ends on the last track. Stop, or roll into the next folder alphabetically? Stopping is predictable; rolling on turns the app into something you leave running. I lean stop, because there's no library to traverse.
O7
Cover screen, folded shut
You said “full player, squeezed”. At ~370dp the deck fits but the segmented control wraps to two rows and the list gets a handful of visible tracks. Worth confirming against a real cover-screen size once you name a device.
O8
Never designed at all
Right-click and long-press menus. A missing or corrupt file. A folder renamed while it's playing. Media keys, MPRIS, the Android notification. The keyboard map. None of these have a design yet, and several will change the library bar.
Candidates: fold-f (unfolded) · tabletop-c (half-open) · mode-c (segmented control) · picker-d (folder grid) · rows-c (track rows). The settled scan behaviour, non-permanent, squeezing the viewport, isn't built yet; scan-b and scan-d each show only half of it.
