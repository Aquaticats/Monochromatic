Design study. The template editor and its two templates, as decided.

Templates for the player's lines

Purpose: show the template editor (D81) as you decided it (D89 to D96, accepted in D98) and the two lines that get a template, which you approved (D99). The page asks nothing; anything you would change goes in the last field.

Every state is authored debug input. Typing is not connected: each view shows fixed template text, and the preview, error lines and help it draws are checked against a reference that computes what the grammar yields. The app has a duration only for the playing track today and draws no supporting line yet, so this previews a line the app cannot fill for every row.

The buttons emit debug events only. No template is stored and no row of the player changes. No production implementation is authorized.

What to look at: the states of the decided editor and its two templates on both panels, at 100% and 200% text. How to respond: if anything should change, write it in the last field, press Prepare reply and paste the prepared text into the chat. This page sends and saves nothing.

The editor's states

The preview is the first thing on one scrolling page (D91). Three states hold focus in the template field with the system keyboard open, and the page rests where Android puts a focused field (D94). Under each image, the page says what of that state is not in view.

What is decided

  • Spelling follows KWGT: formulas between dollar signs, mi(field) for a field of the track, tf(seconds, format) for a duration, tc(mode, text) for case and cutting, and + to join text. There is no conditional and nothing to compare with (D92).
  • Fields: title, file, ext, folder, path, len and peak. There is no artist or album field, because the app reads no tags.
  • Text outside the formulas is always shown, and a field with no value yields nothing (D93). The true peak carries its own unit. The default template is $tf(mi(len), m:ss)$ $mi(peak)$: an analysed file reads 4:35 −1.2 dBTP, one not analysed yet reads 5:12. A separator you write next to an empty field stays in the line, as the changed template shows.
  • The preview shows two files of the open library, one of them not analysed yet. A library is always open; when it holds no track, the preview shows sample values and says so (D95). The preview scrolls with the page (D91).
  • An edit applies as typed while the template is valid. While it has a mistake, rows keep the last valid template. There is no Save step; Reset to default is drawn only when the template differs from the default.
  • A mistake is named under the field in place of the typing help. A formula left open is a mistake.
  • The field list stays under the field; with the keyboard open you scroll to it (D96).

Which lines get a template

Built as the agent's one version (D97) and approved as built (D99).

  • Two templates, listed under Templates in Settings: Track rows, the supporting line studied so far, and Playing track, the line under the playing track's title in the deck. Each editor is titled with its template's name, so the track rows' editor is now titled Track rows.
  • The playing track's default is $mi(track)$ of $mi(total)$ $mi(peak)$: 1 of 16 −1.2 dBTP for an analysed file and 2 of 16 before analysis. On the inner panel the deck in the left pane shows that line. Its fields are the track fields and two more: track, the file's place in its folder, and total, how many tracks the folder holds. mi(track) follows KWGT's own field of that name.
  • Search results are not templated: their second line is the parent folder, which D77 requires so equal names stay apart. Folder names and every title stay as they are.
Read what was and was not checked

The host is a debug activity, not the player. The merged debug manifest disables the production launcher, playback and sweep services. Each view was captured with a fresh hierarchy, exactly one creation of the host since its launch, and the keyboard open only for the scenes whose state holds focus. 7 visits contributed views, out of many attempts while other work held the host's load average between about 45 and 100 on its 16 cores. The others ended without a new view: boots longer than their bound, launches reported as timed out, not-responding dialogs and lost focus; the system's memory-pressure killer also stopped the loop running them once. Views finished before an interruption were kept, and each view's record names its visit. The last visit captured the remaining 37 views and shut down cleanly.

Whether a text is in view is read from its rectangle in the hierarchy, the page's scrolling window and the keyboard's own frame; hierarchy rectangles are not ink bounds. A text whose rectangle touches an edge of the window is reported as at the edge, because the hierarchy cannot tell cut from flush. Where the page rests with the keyboard open is where Android puts a focused field; the study scrolled only the view of the page's end. TalkBack, focus order, speech and contrast were not exercised. Real typing, caret movement by touch, scrolling by hand and inserting a field were not exercised.

Not built yet: with the keyboard open most of the field list is out of view, so inserting a field means scrolling away from the field. That is the next concern of this round.

The published crops keep exact RGB, opacity, dimensions and only essential PNG chunks. No digest of an image is recorded, and nothing is compared with a digest (D88).
