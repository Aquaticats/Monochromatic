Compare the unfolded Search placements

Start in typing at 200% text to inspect the deck above the input method, then switch to the resting 100% state. Open a frame to see the original capture at 100% of design dp. The two color schemes share the same structure.

A. Deck rises above the keyboard (recommended)

Search and results use the right pane. The deck stays bottom-left when the keyboard is closed and lifts when it opens.

  • Pros: Preserves the accepted deck side and resting position; the measured IME does not cover any control.
  • Cons: The deck moves vertically while typing; folder context yields to the keyboard, leaving open space near the top.

B. Deck stays at the upper left

Search and results use the right pane. Playback remains in one fixed upper-left position; folders live underneath when space permits.

  • Pros: The deck does not jump as the keyboard opens; Search stays coherent next to it.
  • Cons: Entering Search moves the accepted bottom deck to the top and relegates folder browsing.

C. Search left, deck upper right

Search and results stay together in the left pane. Playback moves to a crease-cleared upper-right zone.

  • Pros: Search takes the familiar browsing side while all deck controls remain in view.
  • Cons: Playback moves across the crease; the track list underneath competes with Search when the keyboard is closed.

Ranking: A > B > C. A retains the player's settled deck location when not typing, unlike B. B keeps playback on its settled side, unlike C. If vertical motion feels worse than top relocation, prefer B and say why.

Recommended refinements before adoption: Test a taller real keyboard and long query/result names; keep the focused result list scrollable above it; restore a useful empty state without filling the crease with text. No result action or production Search code is included in this study.
