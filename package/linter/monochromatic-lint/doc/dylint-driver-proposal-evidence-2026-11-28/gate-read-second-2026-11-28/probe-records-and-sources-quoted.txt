## package/linter/monochromatic-lint-closure/README.md 183-213
   183	### Toolchain
   184	
   185	The package uses the repository's shared floating nightly,
   186	declared in the root `mise.toml` with the `rustc-dev` component
   187	(a Dylint library links rustc's own crates)
   188	and the tools `cargo-dylint` and `dylint-link` (the owner approved this on 2026-10-18).
   189	`mise install` provisions all three;
   190	nothing else is needed,
   191	and the package has no `rust-toolchain.toml` and no toolchain override of its own.
   192	The exact nightly is whatever `mise.lock` resolves for the `rust` entry.
   193	Dylint builds a library and every package it lints with that nightly,
   194	and `cargo dylint` caches its driver in `~/.dylint_drivers` (the optional `DYLINT_DRIVER_PATH` moves it).
   195	
   196	A floating-nightly upgrade can break the lint source:
   197	rustc's internal API moves between nightlies,
   198	so after `mise.lock` moves the nightly,
   199	build the library and run the tests before relying on the lint,
   200	and fix the source if the compiler's API changed.
   201	The `dylint_linting` and `dylint_testing` crates and the two tools must stay on the same Dylint release.
   202	
   203	#### What a nightly bump has needed so far
   204	
   205	Measured on `nightly-2026-11-16`:
   206	
   207	- No Dylint release had to change.
   208	  Dylint publishes when a nightly breaks its crates;
   209	  the newest `dylint_linting`,
   210	  6.4.0 (published 2026-11-10),
   211	  compiles against this nightly,
   212	  its own lint template pins `nightly-2026-08-20`,
   213	  and the crates and tools were already on 6.4.0.

## package/cargo-shadow/cli/README.md 576-592 (the first cargo on this host's PATH)
   576	## Toolchain and registry settings
   577	
   578	The step's own cargo calls run the first `cargo` on PATH that is not the shadow,
   579	under the toolchain `toolchain.lock.json` pins (`.tools.rust.version`).
   580	The pin wins over an inherited `RUSTUP_TOOLCHAIN` (a warning says so),
   581	so every lockfile the step writes has one format.
   582	The user's own cargo command is not changed:
   583	the shadow starts the PATH candidate under its own name,
   584	so rustup's `+toolchain`,
   585	`RUSTUP_TOOLCHAIN` and `rust-toolchain` files select the toolchain as before.
   586	The search skips every candidate that resolves to the shadow,
   587	and every candidate that is a toolchain launcher whose record (`<launcher>.launch`,
   588	its `real` binary)
   589	names the shadow,
   590	directly or through further launchers,
   591	before it is run:
   592	the shadow does not start itself a second time.

## package/linter/monochromatic-lint/src/closure_cargo.rs 276-305 (rustc-dev probe: rustc on PATH, process cwd and env)
   276	/// What:
   277	///  Explain a missing `rustc-dev` component in the active compiler,
   278	///  unless a replacement `cargo` is in use.
   279	/// Why:
   280	///  The active compiler is the one `rustc --print sysroot` names.
   281	///  A replacement `cargo` (anything but the bare program name) stands for the whole toolchain,
   282	/// so it is not inspected;
   283	///  the decision follows the program the step was given,
   284	///  not the process environment,
   285	///  so a test that passes a stub is independent of the machine's compiler.
   286	///
   287	/// In TS you'd write (pseudocode):
   288	/// ```ts
   289	/// function rustcDevMissing(cargo: Path): string | undefined;
   290	/// ```
   291	pub fn rustc_dev_missing(cargo: &Path) -> Option<String> {
   292	    if cargo != Path::new("cargo") {
   293	        return None;
   294	    }
   295	    let output = match Command::new("rustc")
   296	        .args(["--print", "sysroot"])
   297	        .stdin(Stdio::null())
   298	        .output()
   299	    {
   300	        Ok(done) => done,
   301	        Err(error) => return Some(format!("rustc does not run ({error})")),
   302	    };
   303	    let sysroot: String = String::from_utf8_lossy(&output.stdout).trim().to_string();
   304	    return rustc_dev_missing_in(Path::new(&sysroot));
   305	}
