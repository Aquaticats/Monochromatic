Survey command, the temporary changes, and the environment

Run at the commit the SURVEY_COMMIT line of output.txt names.
The list is files.txt at that commit.
The harness reads each path with `git show <commit>:<path>`,
so the counts are the commit's, not the worktree's later edits.
The whole output is output.txt.

The three temporary changes, all reverted after the run and never committed:

     src/markdown_fragment_joins_survey_tests.rs

SURVEY_M13_DIR holds the copies the shipped fix changes; it is outside the repository,

The three edits were reverted after the run:
git status --short named none of them.

The harness's after-the-fix control was corrected after this run.
The run's harness wrote its control copy but never passed it to the fix,
and its expected count was one an unfixed copy also held,
so that control could not fail.
The kept harness passes the control through the same invocation as the copies,
and expects the text `Aaa bbb, the` / `ccc ddd eee.`,
which holds one break at no boundary before the fix and none after it.
The run's figure does not depend on that control:
all 222 copies changed bytes,
and the corrected control is measured in
figures-the-survey-does-not-count/reported-paragraph-control.txt.
