# The names the library target publishes, one line per name, `<kind> <name>`.
# What: every item another crate can name through `src/native/lib.rs`, and every `pub use` that carries a name out of a
#       module the `pub mod` chain does not reach, each with the reason it is published.
# Why:  publishing is a decision, and a split that moves a private helper to a file of its own must not take that
#       decision by writing bare `pub` where `pub(crate)` or `pub(super)` says the same thing to the caller.
#       Release 0.6.1-alpha.48 did exactly that to 31 names, 7 of them private before the split.
# How:  `source_guard/nothing_becomes_nameable_from_outside_tests.rs` reads this file and fails on a published name
#       without a line, a carried re-export without a line, and a line whose name is no longer published.
#       A name a release adds on purpose takes a line under a reason of its own, naming the commit that added it.
#       A name a split needs only inside the crate takes `pub(crate)`, `pub(super)` or `pub(in path)` and no line.
# How the reading is bounded: a `pub` item written at the first column of a line in a module the `pub mod` chain
#       reaches; a `#[macro_export] macro_rules!`; and a `pub use` whose named module that chain does not reach.
#       `#[cfg(test)]` above a declaration keeps it out. An item inside an inline `mod name { ... }` is not read, and
#       this crate declares no inline module that is `pub`.
#
# The surface the release already had: every name below was reachable at 68af165851 (0.6.1-alpha.47) through a
# `pub mod` chain, a `#[macro_export]`, or a public re-export out of a private module. The release that followed
# moved and split files without publishing any of them anew, which is why none of them needs a reason of its own.
