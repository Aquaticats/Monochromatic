# Auto-mode instruction authority root

## Accepted decision

The migration requires code-owned source authority,
priority,
and scope.
The current native input chain establishes original capture identity and system-message placement,
not the authority of that source.
Do not restore the removed numeric-priority claim merely because the owner tests pass.

The existing bootstrap selector explicitly leaves priority and delegation unestablished.
The real producer,
observer,
collector,
and budget integration passed in `proc_8d6d` without a provider call.
That verifies custody and currentness,
not a policy authority root.
The user selected trusted-bootstrap registration (option A) on 2026-10-07.
This explicitly accepts host assignment of source authority and scope as policy configuration,
separately from the previously accepted human-confirmation workflow.

## Trust boundary

Allow the trusted host bootstrap to register a governing source with its actual authority tier and scope.
That original registration,
not a filename,
transport role,
model estimate,
or caller-created record,
would supply the authority premise.
Keep registration within the existing source owner and retain its original occurrence and currentness checks.
Do not introduce a parallel global registry or infer complete instruction coverage from a registration.

For example,
a host registration explicitly designating a source as system instructions would be distinguishable
from the same text merely appearing in a serialized system message.
The registration is a deliberate policy assignment,
not a claim that transport placement proves authority.

The benefit is an implementable authority root without fabricated proof.
The cost is trusting the host's authority assignments as policy configuration.
Qualified interpretation,
complete source coverage,
delegation,
and whole-operation evidence remain separate requirements.

## Alternative

Do not introduce this authority root.
Require an independently authenticated authority or delegation input before admitting a source's priority.
This avoids the additional trust assumption,
but the current owner interfaces provide no such admitted input,
so automatic policy resolution remains unresolved.

## Recommendation and status

Prefer explicit trusted-bootstrap registration to pretending that observed placement establishes authority.
Implement authority registration in the existing source owner,
with immutable startup declarations and original source/request binding.
The accepted decision does not authorize production changes,
new paid trials,
source-hash locking,
or confidence thresholds.
