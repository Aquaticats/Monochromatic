# Expanded Depot CI cost and critical-path model

The permanent allocation must retain heavy use of GitHub-hosted runners themselves.
GitHub orchestration of Depot-managed workers does not count as GitHub-hosted execution.
The model must compare workload assignments within that accepted hybrid,
rather than optimize toward replacing GitHub's own compute with Depot.

using the approved USD 200 monthly ceiling and Developer baseline.

## Measured dependency paths

The repeated four-CPU graph has one shared Node build producer,
parallel Node consumer branches,
an independent Rust branch and browser consumers.
The source-bound longest path is shared builds followed by `modules-b` in both GitHub-hosted and
both Depot GitHub samples.
In both corrected-native samples it is shared builds followed by `modules-a`.
The measured node intervals along those paths are 1071.808 and 1072.071 seconds on public GitHub,
356.930 and 369.999 seconds on Depot GitHub,
and 353.253 and 350.930 seconds on corrected native Depot.
The parent elapsed graphs include a separately retained 1.152 to 2.636 seconds of control/dependency gaps.
Rust is not on the longest dependency path in any of these profiles
([exact path arithmetic and original graph sources](../audit/depot-expanded-graph-critical-path-2026-10-18.evidence.json)).

Those elapsed paths contain source failures and different amounts of budget-limited work.
They identify the measured wait within each profile,
not a complete-CI performance ratio.
Rust caching can shorten its own command without producing the same reduction in the parent graph;
the concurrent CPU allocation also prevents treating sibling improvements as independent additive savings.
The completed shared-build and Rust phase comparisons retain their separate repeated measurements in the
[evaluation report](depot-expanded-ci-evaluation.md).
