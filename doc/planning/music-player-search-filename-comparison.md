## Comparison boundaries

### Placement

Hold identifying information constant:
compare the incumbent complete filename in the title with a stem-first
title retaining the exact literal suffix in supporting information.
Do not call a suffix an audio format.
Use authored fixture strings,
not a new extension parser.
A folder with a dotted name keeps its literal name;
item kind does not come from a dot.

The purpose is to inspect scanning,
wrapping and identifying information,
not to presume that moving suffixes saves height.
Retaining suffixes in this placement control does not select permanent
suffix visibility.

### Visibility

Independently compare always-visible suffix text with omission where the
explicitly authored fixture scope establishes no ambiguity.
Include an unambiguous track:
collision-only samples cannot distinguish those policies.
If conditional visibility remains a candidate,
include a partner outside displayed results and state the authored scope.
Filtered,
off-screen or later partners must not silently change identity.
No matching or collision-detection algorithm is selected or implemented.

Same-parent suffix-distinct names need a stable visible distinguishing
cue before activation.
The existing ambiguous suffix-omitted control is not a usable option.
Equal complete filenames also need useful ancestor context.

### Required baseline and verification

Before claiming a comparison with the ordinary player,
capture its actual screen with matched literal names,
real chrome,
available width,
folder/page context and applicable current-track decoration.
Use disposable data and record panel,
font scale and theme.
Do not substitute the copied row mechanism or force Search geometry
onto the player.
If this setup exceeds authorization,
retain the baseline gap instead of claiming it complete.

A Search-only comparison can be reported as such;
it cannot establish the unrendered incumbent-player comparison.
Static rendering still does not verify playback,
activation,
speech,
matching or full player behavior.

Use the existing short/long pairs,
equal-name ancestor cases and literal edge names.
Verify both panels,
100%/200% text and light/dark with the keyboard closed.
Preserve minimum spacing.
Inspect actual distinguishing characters and context;
measure geometry rather than inferring density.
Do not add capacity claims without a comparison that actually tests them.

### C. Copy the ordinary-row replica into Search

Pros:

Cons:

rather than adopting a treatment that hides them.
This ranks investigation paths,
not selected extension visibility or placement.
