## Proposed private module

Put lifecycle occurrence changes inside the SDK implementation that owns canonical manager state.
Keep the existing registry responsible for constructor ownership,
exact session/manager pairing,
suspension,
and retirement.
Do not duplicate those responsibilities in another host registry.

The proposed interface supplies an opaque root occurrence through a trusted reader.
It is an identity observation,
not a human credential or permission.
An occurrence changes before a possible structural mutation can take effect.
Restoring the old leaf or bytes cannot restore the old occurrence.
A genuine same-root append does not itself change the lifecycle occurrence.
Content/source freshness remains a separate check.

The implementation must also close the measured ways of bypassing that observation:

-   Keep canonical data private and copy admitted inputs and returned data.
-   Make internal writer helpers inaccessible to external callers.
-   Protect the manager's method surface,
    including reads,
    rather than trusting replaceable own getters.
-   Make cached and prototype calls reach the intrinsic mutation marker.
-   Inventory every native writer before admitting its operation category.
    Unknown writer coverage remains a failed prerequisite.

The prototype should first test an opaque occurrence value rather than callbacks into host code.
This avoids adding callback exceptions or reentrancy to native mutation control flow.
Whether that observation can meet the registry's cancellation and failure contracts is a test question,
not an established result.

Examples the same consumer interface must distinguish:

-   An ordinary assistant append preserves the active lifecycle lease.
-   A pending operation suspends release before any asynchronous preparation.
-   A cancelled operation resumes only after proving its native occurrence stayed unchanged.
-   A cached `branch` call changes the occurrence before changing the leaf.
    Returning to the original leaf does not revive a prior receipt.
-   A spoofed getter or exposed internal-loader route cannot mint a fresh owned observation.
-   A failure after possible mutation leaves the old occurrence unusable while preserving the original exception.

## Scope and risks

The main repository remains documentation-only during this prototype.
Keep the installed SDK,
production auto-mode,

consumed evidence,

and current human permission unchanged.

Protecting a method surface may remove instance-hook techniques used in existing diagnostic fixtures.
Those hooks are not a production compatibility promise;

Source changes may affect resume,
fork,
compaction,
custom data,
recovery omission,
and other methods not exercised by the selected consumer profile.
The writer inventory and consumer coverage must name these surfaces explicitly.
A passed import or selected fixture cannot establish complete compatibility.

This is not a JavaScript security compartment against arbitrary hostile code in the same process.
The controlled host,
construction owner,
module loading,

Instruction authority and authenticated human permission remain separate work.

## Recommendation and alternative

### A: Prototype the SDK-owned custody module

Recommended.
It targets the measured mutation routes at their owner and gives the existing lease module
an observation that does not depend on extension-event timing.
Its cost is a structural private SDK experiment and further native consumer qualification.
It does not authorize installation or adoption.

### B: Stop structural SDK prototyping at the current findings

This avoids additional private SDK changes and preserves the accepted diagnostic results.
The tradeoff is that mutation custody remains unqualified,
so production admission relying on these leases stays blocked.
It does not turn cooperative hooks or equal snapshots into sufficient evidence.

Ranking:
A > B,
because A tests a path toward the required occurrence semantics,
while B leaves the demonstrated custody prerequisite unresolved.
Both keep production admission blocked until its actual prerequisites are met.
