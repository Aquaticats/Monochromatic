## Example and boundary

Suppose an established developer instruction says:

> For this operation,
>  follow this exact quoted rule:
>
> Do not overwrite existing files.

The Markdown block in this proposal presents the example;
it does not itself register either sentence as a governing instruction.
The candidate implementation would retain separate original handles for the actual adopting instruction,
the actual quoted unit,
and the original operation.

A semantic estimate may identify express incorporation and interpret the quoted rule's conditional meaning.
It cannot authenticate either source,
assign the quoted speaker an authority tier,
expand the adopting instruction's scope,
or select the final action verdict.
Paragraph shape and matching text do not independently establish an operative adopting instruction.

## Options

### Express same-source incorporation

An independently established governing instruction may incorporate exact quoted text from the same original source
within its existing operation scope.
Code would enforce this rule;
separately admitted semantic estimates would identify the incorporation and the target's meaning.
The target receives no more authority or scope than the adopting instruction.

This follows the source's explicit direction without per-quotation host configuration.
It requires qualified interpretation of both the adopting unit and the reference.
Amendments,
ambiguous references,
extra independent norms,
incorporation chains,
and unresolved conditions remain unsupported.
Adoption itself adds no permission.

### Explicit host registration of the quoted unit

Quoted text becomes an instruction only when trusted bootstrap separately registers that original unit and scope.
A semantic incorporation estimate alone would not make it operative.

This makes the authority assignment explicit at configuration time.
It requires an additional registration contract and per-unit configuration,
and may leave an otherwise explicit governing instruction unconsumed until configuration changes.
No such registration API is currently implemented.

### Keep this incorporation route unresolved

Do not add either quoted-unit admission route yet.
Preserve the scope obligation and continue other migration work.

This introduces no new composition policy.
It also leaves operations depending on incorporated quotations unresolved,
even where their wording expressly requests incorporation.
It is not a rule that quotations supply permission,
an automatic denial,
or an automatic approval request.

## Ranking and risks

Ranking:
 express same-source incorporation > explicit host registration > retaining unresolved scope.
Express incorporation follows established instructions without per-unit configuration.
Host registration can resolve scope explicitly but imposes that configuration burden.
Retaining unresolved scope is preferable to fabricated authority,
but resolves none of these cases.

No option establishes exhaustive request origins or governing-domain coverage.
Cross-source authority transfer,
production probability thresholds,
provider trials,
and installed activation are outside this proposal.
