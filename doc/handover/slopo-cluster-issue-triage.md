## Review method (per user instruction 8)

Every one of the 1008 clusters gets an individual recorded verdict, in theme order so related
clusters are judged together:

1. Generate a condensed digest per cluster (paths, line ranges, signature or context line, first
   ~200 characters of each distinct body).
2. Read the digest, inspect the real files in the repo where the verdict depends on facts
   (generated headers, tracked status, consumers, package ownership).
3. Where a mechanical invariant makes the verdict certain (for example both units are the same line
   range in two byte-identical files), verify the invariant programmatically per cluster and record
   `pattern-verified` plus the check that passed. Otherwise record `digest-read` or `file-inspected`.
4. Append one ledger row per cluster: cluster number, hash, theme, verdict category, evidence,
   review mode, issue number (filled when the issue is opened).

Verdict categories:

- `DEDUPE-ARTIFACT`: duplicated generated or vendored artifact; fix the producer or layout.
- `REMOVE-MIRROR`: a mirrored source tree that should import from its owner.
- `EXTRACT-SHARED`: real duplicated logic; extract a shared helper, module, or crate.
- `CONSOLIDATE-CONFIG`: duplicated configuration or manifest content.
- `CROSS-LANGUAGE-DRIFT`: parallel implementations in different languages; remediation is a rewrite,
  not a shared function.
- `GENERATOR-SIDE`: duplication lives in generated corpora; fix the generator.
- `INTENTIONAL-VARIANT`, `STRUCTURAL-IDIOM`, `COINCIDENTAL-SHAPE`, `BOILERPLATE-TRIVIAL`,
  `TEST-OR-GENERATED`: dismissal categories matching `slopo.ignore.txt`; propose ignore entries.
- `UNCERTAIN`: competing actions are equally valid; the issue must name all of them.

### Structural finding: the git-policy `src/optional` tree is generated

Root `file-enforcer.config.ts` generates `package/git-policy/cli/src/optional/**` from canonical
package sources through three mirror closures (`mirrorRepositoryPolicy` at 2284-2299,
`mirrorForbiddenStringsPolicy` at 2308-2319, `mirrorMarkdownLintPolicy` at 2326-2337), rewriting
`@monochromatic-dev/git-policy-api/ts` and `@monochromatic-dev/git-policy-markdown-lint/ts` imports to
relative paths and prepending a `Generated from ... by file-enforcer; edit canonical source owner.`
header. Verified: 18 files are mirrored (8 repository-policy, 6 forbidden-strings, 4 markdown-lint)
and 18 files in that tree carry the header. `package/git-policy/cli/package.json` lists only
`@monochromatic-dev/git-policy-repository` as a workspace devDependency, so the mirror is how
`src/authoring.ts` reaches the api, markdown-lint and forbidden-strings policies.
`doc/decision/npm-publishing.md:81-86` records that the `./ts` subpath is stripped at publish and the
published surface is the bundled artifact, so the mirror is not needed for published-source
self-containment.

shape as the transpiled `.js` pairs. Per-hash dismissal is unstable for them, because editing a
canonical file changes both bodies and therefore the cluster hash. The issue must present the
competing actions: keep the mirror and accept the churn, delete it and add the three packages as
workspace devDependencies so rolldown bundles them, or emit the copies into an already-excluded build
directory.
