# Replace the auto-mode decision core

Accepted on 2026-10-15 after the
[whole-system review](../planning/pi-auto-mode-whole-system-review.md).
The user authorized replacement and explicitly requested avoiding overengineering.
One decision owner will select current context, assess it, resolve policy, and apply scoped confirmation.
Retain the native owners of prepared arguments, operation identity, source freshness, cancellation, and execution.
Separate bypass execution from semantic program-profile admission.

Use existing functions and dependencies wherever their behavior satisfies the contract.
Remove replaced forwarding and inactive paths instead of introducing a framework or parallel implementation.
Local provenance retention must not determine outbound assessment scope.
Keep complete current policy and the legacy visible-message window,
and let confirmation satisfy only the prerequisite that accepts that confirmation channel.
The existing 15-second preparation-inclusive budget and transport-failure behavior remain in force.

The review contains the rejected alternatives and required consumer checks.
Implementation and verification status remain in the
[current frontier](../handover/pi-auto-mode-current-frontier.md).
