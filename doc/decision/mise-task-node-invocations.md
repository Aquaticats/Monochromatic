# Reducing node invocations in mise tasks

## Status

Accepted,
 2026-06-10.

## Context

Many mise tasks set `shell = "node -e"` (one node process) whose body did nothing
but read mise's shell-escaped `usage_args`,
 split it,
 and
`execFileSync('node', [entry, ...args])` (a second node process).
 The first node
was pure ceremony:
 cross-platform argument forwarding to an entry that is itself a
standalone CLI (shebang,
 reads `process.argv.slice(2)`,
 sets `process.exitCode`).

This was investigated under the question "reduce node usage in mise tasks",
 in two
axes the phrase can mean:
 fewer node processes,
 and less inline `node -e` script in
TOML.

Empirical findings that shaped the decision (verified,
 not assumed):

- A task with a plain `run` and no `usage` spec receives post-`--` arguments from
  mise appended as a real argv vector,
   preserving spaces.
   A `usage` spec instead
  consumes the args into `usage_*` env vars and they do not append.
   Tera
  `{{arg()}}` also forwards but is deprecated (removed in mise 2027.5.0).
- In-process `await import()` of a top-level `.ts` entry under `node -e` runs it
  (type stripping,
   shebang,
   argv forwarding all work) and `process.exitCode`
  propagates.
   But an entry guarded by `if (import.meta.main)` does not run on
  import (the guard is false),
   so import silently no-ops it.

## Decision

Two parts.

### Collapse the pure forwarders (done)

Where the `node -e` wrapper only forwarded arguments,
 delete it and let mise
forward natively with a plain `run = "node <entry>"` and no `usage` spec.
 This
removes the second node process,
 removes the inline script,
 and fixes a latent bug
where the old `.split(' ')` tore space-containing paths into two arguments.

Shipped across three commits:

- Per-package `run` and `count` tasks:
   `package/cli/{fy,git,terminal-exec,rgffplay,vmsync,git-clone-size,mvm,markdown-lint}/mise.toml`
   and `package/module/token-count/mise.toml`.
- Root `page:weight` (its entry validates a missing arg itself) and
  `lint:markdown` / `format:markdown` (the `.` default already lives in
  `package/cli/markdown-lint/src/run.ts`,
   so the mise-body default was redundant).
- Root `catalog:tighten` (its entry reads `--dry-run` from argv;
   matches the
  README's documented `mise run catalog:tighten -- --dry-run`).

Root tasks are edited in the `mise.no-env.toml` source and `mise.toml` is
regenerated by file-enforcer.

### Keep `runWorkspaceNode` as a subprocess dispatch (do not collapse)

The `dispatch_workspace_node` var in `mise.no-env.toml` defines `runWorkspaceNode`,
used by ~182 dispatch tasks (`lint:oxlint`,
 `lint:types`,
 `format:oxlint`,
`build:css`,
 `prepare:playwright`,
 and per-package overrides).
 Its `node -e` does
real,
 cross-platform work:
 it resolves the monorepo root (so a package task can
locate a sibling package from any cwd) and picks the built `dist/final/node/*.mjs`
over the `src/*.ts` source.
 That first node cannot be deleted.

The second node (the dispatched entry) could be turned into an in-process
`await import()`.
 We measured it and decided against.

## Rationale

Benchmark (node 26.3,
 hyperfine,
 this machine),
 dispatching the same no-op entry
through the real `runWorkspaceNode`,
 spawn-the-entry vs import-the-entry:

```text
node-level (isolates the saving):
  spawn   56.9 ± 1.9 ms
  import  37.3 ± 1.1 ms   -> ~20 ms saved per dispatch call (one node cold start)

mise-level (realistic, two worktrees, includes ~135 ms mise startup):
  baseline  190.0 ± 2.7 ms
  collapse  173.5 ± 2.1 ms   -> ~16 ms saved, 1.10x faster

context: a real lint:oxlint (fy/cli) runs 466 ± 8 ms
  so the saving is ~4% of one dispatch step
```

Against that ~18 ms per call:

- The saving is small per call and largely hidden behind parallel `fanout`
  (packages dispatch concurrently,
   so the wall-clock saving is a fraction of the
  serial `182 x 18 ms` upper bound,
   bounded by the slowest package).
- It removes no `node -e` wrapper,
   so it does nothing on the inline-script axis.
- The cost is a real correctness footgun:
   `runWorkspaceNode` would become async,
   so
  every one of ~12 call sites needs `await`,
   and a forgotten `await` silently
  no-ops the task rather than failing loudly.
   It would also force rewriting
  `package/dev-script/task-util/src/tsgo-filter.ts`'s working `import.meta.main`
  guard to the `argv[1]` idiom,
   and commit the codebase to a convention ("no
  dispatched entry may use `import.meta.main`") that one entry currently violates.

The marginal,
 parallelism-hidden gain does not justify the fragility.

## Consequences

- The `node -e` plus `runWorkspaceNode` shape stays.
   New dispatch tasks should keep
  using it rather than hand-rolling a collapse.
- Since 2026-07-10 the task shells spell the eval as
  `shell = "node --input-type=module-typescript -e"`;
   bare `node -e` relied on Node module-syntax detection for top-level `await`,
   which some environments disable
  (see `doc/troubleshooting/node-eval-module-detection.md`).
- Other remaining `node -e` usage is load-bearing and intentionally untouched:
  `fanout` (depth-filtered parallel `mise run` orchestration),
   the test runners
  (`run_test_files`,
   `watch:test:unit`,
   podman browser/e2e),
   tofu's
  external-program tests (the spawned node is the contract under test),
   and the
  music-player / terminal cargo dispatch (node branches platforms then spawns
  cargo or podman).

## When to revisit

Reopen if any of these change:

- mise gains a native,
   cross-platform way to run a workspace entry with
  built-vs-source selection,
   removing the need for the dispatch node entirely.
- A profile shows mise task startup (not the underlying oxlint/tsgo/postcss work)
  is a measured bottleneck in a real workflow.
- The dispatched entries are refactored to a uniform `export function main()` shape
  that makes in-process import robust without relying on top-level side effects.
